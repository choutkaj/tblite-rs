# tblite-rs 0.2.0

`tblite` and `tblite-sys` now bind tblite **0.8.0**. The release also attaches
redistributable tblite runtime bundles for Windows x86-64, Linux x86-64 and
macOS arm64.

## Install

```toml
[dependencies]
tblite = "0.2.0"
```

Rust 1.85 or newer and a native **tblite 0.8.x** are required. Cargo does not
download or build Fortran. Set `TBLITE_DIR` to one of the attached bundles, or
build tblite with the
[installation guide](https://github.com/choutkaj/tblite-rs/blob/v0.2.0/docs/installation.md).

## Changes

- Both crates require tblite 0.8.x. They reject tblite 0.7.x at build time and
  at run time.
- Raw bindings to all 123 public C functions in tblite 0.8.0.
- `tblite::has_feature` reports whether the loaded library has ddX, HDF5,
  TREXIO, MPI or ScaLAPACK.
- `Calculator::add_orbital_localization` and the `lmo-foster-boys`
  post-processing keyword add Foster-Boys orbital localization.
  `CalculationResult::localized_orbital_coefficients` and
  `CalculationResult::localized_orbital_centers` return the localized orbitals
  and their centres.
- `Context::set_partition` and `Context::set_mpi` set tblite's work partition
  and MPI communicator.

Results change slightly from tblite 0.7.0. Across the 43 MB16-43 structures,
the largest changes are:

| Method | Energy (Eh) | Gradient component (Eh/Bohr) |
| --- | ---: | ---: |
| GFN1-xTB | 3.9e-10 | 5.2e-11 |
| GFN2-xTB | 4.7e-9 | 2.2e-7 |
| IPEA1-xTB | 2.0e-9 | 2.4e-10 |

GFN2-xTB partial charges change by up to 1.6e-6 e and dipole components by up
to 8.3e-6 e Bohr.

## Runtime bundles

| Asset | Runs on |
| --- | --- |
| `tblite-0.8.0-windows-x86_64.tar.gz` | Windows 10 and later, x86-64 |
| `tblite-0.8.0-linux-x86_64.tar.gz` | Linux x86-64 with glibc 2.28 or later |
| `tblite-0.8.0-macos-aarch64.tar.gz` | macOS 11 and later on Apple silicon |

Each archive holds one folder, named after the platform. The folder contains
tblite 0.8.0 as a shared library with the runtime libraries it loads (GCC's
Fortran and OpenMP runtimes, or LLVM's OpenMP on macOS, and OpenBLAS), the C
headers, a relocatable `pkgconfig/tblite.pc`, every licence text, and
`SOURCES.md`, which lists every file's checksum, source and build recipe. CI
built all three from this release's commit with pinned toolchains.

An application ships `lib/`, `licenses/` and `SOURCES.md`, and states that it
uses tblite under the LGPL. The
[distribution guide](https://github.com/choutkaj/tblite-rs/blob/v0.2.0/docs/distribution.md)
describes the layout, how executables find the libraries on each platform,
and the licence obligations. The macOS libraries carry ad hoc signatures only;
sign them with the application's identity.

## Validation

CI passed on Linux with full and minimal native builds, on macOS ARM64 and
x86-64, and on Windows/MSVC. Linux and macOS also passed with static tblite,
and Linux passed the native memory checks. The tests and examples
passed against each of the three bundles. The MB16-43 benchmark passes all
**129 native/Rust calculation pairs** with the Windows, Linux and macOS bundles.
See the
[benchmark reports](https://github.com/choutkaj/tblite-rs/tree/v0.2.0/benchmarks/mb16-43).

## Known limitations

- Native calls are serialized; native handles are neither `Send` nor `Sync`.
  tblite can still use its internal OpenMP parallelism.
- ddX, HDF5, TREXIO, MPI and ScaLAPACK depend on the native build. The bundles
  have ddX, but not HDF5, TREXIO, MPI or ScaLAPACK. Without MPI, a calculation
  split into more than one part fails.
- The macOS bundle is for Apple silicon only.
- No optimizer/MD driver, Cargo-triggered native builds, Windows static linking
  or fully static executables are provided.
- The tblite logger has a known small native allocation leak per used logger
  instance when replaced or destroyed. Other ABI adaptations and native
  limitations are described in the
  [safety notes](https://github.com/choutkaj/tblite-rs/blob/v0.2.0/docs/safety.md).
